# 跨页表格拼接当前最优效果深度调研

调研截止日期：2026-08-02

## 结论先行

截至调研日期，文献中**不存在一个可以跨数据集直接比较的统一“跨页表格拼接 SOTA”**。原因是现有论文分别评估完整文档抽取、跨页表格子集、逐页识别后的合并、结构完整性或仅续接分类，指标含义并不相同。

在目前核验到的证据中，可以给出以下分层结论：

1. **最可信的公开大规模内容 exact-match 结果：**PubTables-v2 Full Documents 上，Claude Opus 4.6 的 `Acc_Con = 0.2452`。这是内容感知的表格 exact-match 聚合分数；测试文档都含有多页或多栏表格，但评分同时包含文档中的单页表，因此不能解释成“24.52% 的跨页表格单独拼接完全正确”。[1]
2. **最可信的公开大规模结构 exact-match 结果：**同一设置下 Claude Opus 4.6 的 `Acc_Top = 0.5799`。它要求表格拓扑完全匹配，但忽略单元格文字内容。[1]
3. **显式“逐页识别 + 跨页合并”流水线的最好内容 exact-match 结果：**POTATR + merging 的 `Acc_Con = 0.2176`；对应 `Acc_Top = 0.4234`、`GriTS_Con = 0.8269`。该方法使用续接分类器和简单纵向拼接，没有显式解决列对应、重复表头或拆分行。[2]
4. **最直接的跨页表格专用子集软相似度结果：**LingDT-VL-OCR 在 FinDocBench 的 472 张跨页表格上报告平均 `TEDS = 0.8915`。这是编辑距离相似度，不是完全正确率；论文没有报告 exact match，也没有给出其他方法在同一跨页子集上的对比结果。[3]
5. **目前找到的最高整表结构零错误类结果，但可信度较低：**VCCT 在 300 张私有电网故障报告跨页表格上报告 `SIR = 82.0%`。SIR 要求无列错位、行完整无遗漏且表头精确对齐，但不要求单元格内容完全正确；论文另报单元格数据准确率 `86.3%`。该结果来自未评审 SSRN 预印本，数据和代码未公开，文献引用还存在明显可疑项，因此不能称为通用、可复现的 SOTA。[4]

因此，若需要一句最严谨的回答：

> 公开大规模基准上，目前核验到的最高内容完全匹配分数是 PubTables-v2 上 Claude Opus 4.6 的 `Acc_Con = 0.2452`；直接针对跨页表格子集的最新强结果是 FinDocBench 上平均 `TEDS = 0.8915`，但它不是完全正确率；尚未找到公开可复现研究在“固定页面识别结果、只评估跨页对齐与拼接”的专用测试集上报告整张表结构和内容完全正确率。

## 指标不能混用

| 指标 | 判断的内容 | 完全正确类指标 | 能否直接表示拼接完全正确 |
|---|---|---:|---|
| `Acc_Con` | 表格拓扑和单元格内容都必须完全匹配 | 是 | 最接近，但 PubTables-v2 的 Full Documents 结果同时受检测、单页识别、跨页识别和拼接影响 |
| `Acc_Top` | 表格拓扑必须完全匹配，忽略文字内容 | 是，结构层面 | 可以表示结构完全正确，不能表示内容完全正确 |
| `SIR` | 整表无列错位、行无遗漏、表头对齐 | 是，作者自定义结构层面 | 接近结构拼接完全正确，但不是标准指标，也不检查全部单元格内容 |
| `GriTS_Con` | 网格和内容的平均软匹配 | 否 | 高分仍可能包含多处行列或文字错误 |
| `TEDS` | HTML 树结构和内容的编辑距离相似度 | 否 | 高分不等于整表零错误 |
| 续接 F1 | 两个页面片段是否属于同一张表 | 否 | 只判断“要不要拼”，不判断“怎样对齐并拼对” |

PubTables-v2 将传统的一对一表格指标扩展到了一个文档中多张预测表与多张真实表的集合匹配。`Acc_Con` 仍然只给完全匹配的表计分，但其 Full Documents 数值是跨整个测试集合聚合的表级 exact-match 结果，不是“每篇文档内所有表都完全正确”的文档 exact match。[1]

## 对各项“最好结果”的解释

### 1. 为什么不能把 Gemini 的 0.9309 当成最好拼接准确率

`GriTS_Con = 0.9309` 是网格与内容的软相似度。一个长表即使有少量列错位、漏行、重复表头或分页处拆分行错误，仍可能得到很高的平均相似度。Gemini 在同一表中的 `Acc_Con` 只有 `0.2025`，正好说明“整体看起来很像”和“整张表一个错误都没有”是两件事。[1]

### 2. 0.2452 是否就是跨页拼接的严格 SOTA

它是目前核验到的**最可信公开大规模、内容感知 exact-match 证据**，但只能称为 PubTables-v2 Full Documents 端到端设置中的最好结果。该评测同时包含：

- 页面内表格检测和结构识别；
- 文档中多张表的匹配；
- 单页表格；
- 多栏或多页表格的识别与合并；
- 单元格文字抽取。

因此，它没有隔离跨页拼接模块本身。现有论文尚未公开报告“输入已经是正确的页面表格片段，只考察跨页列、表头和拆分行对齐”的独立 `Acc_Con`。

### 3. VCCT 的 82.0% 是否更强

只看数字和定义，`SIR = 82.0%` 确实是本次检索中最高的整表结构零错误类结果。但它与 `Acc_Con` 不等价：SIR 不要求每个单元格文字都正确，而且使用私有的 300 张领域表。它最多能作为“私有领域内的高结构完整率声明”，不能推翻公开基准上的结论，也不能作为论文主基线的唯一依据。[4]

### 4. LingDT-VL-OCR 的意义

LingDT-VL-OCR 是重要的新近直接证据，因为它明确只在 472 张跨页表上评估合并后的表，并得到平均 `TEDS = 0.8915`。但论文只给自己的单一结果，未报告 exact match，也没有展示同一跨页子集上其他模型的结果，因此无法确认它在 FinDocBench 上是否为严格 SOTA。[3]

## 为什么仍然有研究空间

现有结果呈现出很稳定的差距：软相似度可以达到约 `0.89-0.93`，而公开大规模内容 exact-match 仍只有约 `0.20-0.25`。这说明模型通常能恢复大部分内容，但仍会因为少数结构错误导致整表失败。现有公开方法没有把以下关系作为主要预测目标并单独评估：

- 下一页的每一列对应上一页哪一列；
- 下一页开头是否为重复表头，应该删除还是保留；
- 分页处的一行是否被截断，需要与下一页首行合并；
- 跨页后出现列合并、拆分或局部子表头时如何恢复；
- 页面识别错误和拼接错误分别造成多少性能损失。

这正是“固定页面提取器后，研究结构对齐感知的跨页表格恢复”仍有意义的原因。

## 对本项目的直接建议

主实验应设置两个轨道：

1. **端到端轨道：**使用 POTATR/TATR 或其他固定页面提取器，和已发表的续接分类 + 纵向拼接基线比较，报告 PubTables-v2 官方 `Acc_Con`、`Acc_Top`、`GriTS_Con` 和 TEDS。
2. **对齐隔离轨道：**给模型真实页面片段或经过人工校验的页面结构，只评估跨页列匹配、重复表头、拆分行和最终整表重建。这个轨道应新增“跨页表结构 exact match”和“跨页表结构 + 内容 exact match”，并按跨页数、列数、拆分行和复杂表头分层。

如果只做第一个轨道，改进可能被页面识别误差掩盖；如果只做第二个轨道，则容易被质疑不是完整文档分析系统。两者同时报告，才能证明方法既解决了拼接问题，又能嵌入版式/表格分析流程。

## 检索边界与可信度

本轮在已有系统检索基础上，继续使用 OpenAlex、arXiv 和聚焦网页检索，覆盖 `cross-page table`、`multi-page table`、`table continuation`、`table merging`、`table stitching`、`exact match`、`structure integrity` 等组合，并核对 PubTables-v2、POTATR、LingDT-VL-OCR 和 VCCT 原文。没有发现另一项公开研究在跨页表格专用公开测试集上报告可复现的结构与内容整表 exact match。

“没有发现”不等于数学意义上的不存在。特别是企业技术报告、非英文论文、未索引论文和私有评测可能仍有遗漏。本文档因此采用“截至日期内核验到的最好公开证据”，而不使用无条件的“世界最好”。
