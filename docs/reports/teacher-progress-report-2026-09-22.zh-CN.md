# 文档级跨页表格恢复研究阶段进展汇报

日期：2026-09-23

研究主题：基于 PubTables-v2 的文档级跨页表格恢复

汇报性质：阶段性进展与下一步方案讨论（宏观汇报版）

## 1. 当前研究目标

本项目研究完整文档中的跨页表格恢复。目标不仅是识别单页上的表格，还要判断不同页面中的表格片段是否属于同一张逻辑表，并进一步恢复：

- 跨页列对应；
- 重复表头；
- 跨页拆分行和拆分单元格；
- 多个页面片段之间的全局一致性；
- 最终完整逻辑表格的结构与内容。

最终主基准是固定版本的 [PubTables-v2 Full Documents](https://arxiv.org/abs/2512.10888)。项目将分别报告 `PDF-text-assisted` 和 `image-only` 两条赛道，避免把不同输入条件下的结果直接比较。

## 2. 当前已经完成的工作

目前完成了四类基础工作：

1. 固定 PubTables-v2 数据版本，并完成 Full Documents 数据准备、标准化和官方跨页标签审查；
2. 建立统一的输入清单、覆盖检查和离线评测流程；
3. 完成 TATR-v1.1-Pub 在 Cropped Tables validation 上的正式全量评测；
4. 完成 dots.ocr 历史结果的协议复核，并验证新的严格评测流程可以运行。

当前阶段已经具备可信的页面级基线和评测基础，但跨页关系建模、结构对齐和完整逻辑表重建尚未正式展开。因此，现在的工作属于“研究基础和基线建立完成，准备进入核心方法阶段”，还不能表述为已经解决跨页表格恢复。

## 3. 当前主要实验结果

### 3.1 TATR-v1.1-Pub

TATR-v1.1-Pub 已在 PubTables-v2 `Cropped Tables/val` 全部 13,384 张长表和宽表上完成评测。经过完整评测复核，正式结果为：

| 指标 | 结果 |
| --- | ---: |
| GriTS-Top | 0.8848 |
| GriTS-Con | 0.8704 |
| Acc-Top | 0.3897 |
| Acc-Con | 0.3827 |

其中，GriTS 衡量局部结构和内容相似度，Acc 衡量整张表格是否严格完全正确。因此，这组结果说明：

- 模型能够恢复较多局部结构和内容；
- 约 38.27% 的困难裁剪表达到结构和内容严格完全匹配；
- 对于长表、宽表和复杂结构，仍存在明显的整体结构改进空间；
- TATR 可以作为后续跨页研究的页面解析输入，但它本身不负责判断跨页续接或恢复跨页结构。

该实验属于 `PDF-text-assisted` 页面级基线，不能直接表述为 Full Documents 跨页恢复结果。

### 3.2 dots.ocr

dots.ocr 代表 `image-only` 的端到端文档视觉模型路线。接管项目之前已经完成过一次较大规模的 Full Documents 历史运行，覆盖 validation 中全部935篇目标文档的3,522个真值表格页，结果为：

| 指标 | 历史结果 |
| --- | ---: |
| GriTS-Top | 0.6564 |
| GriTS-Con | 0.6216 |
| Acc-Top | 0.2760 |
| Acc-Con | 0.1380 |

这组结果说明，dots.ocr 已经在较大规模的完整页面图像上完成过页面级表格检测、文字识别和结构生成，因此是当前重要的 `image-only` 参考基线。

但复核后确认，该运行只处理了真值表格所在页面，没有覆盖 validation 的全部13,871页，也没有执行 continuation 判断和跨页合并。因此，这组结果应表述为“Full Documents 表格页筛选、逐页抽取的历史参考”，不能表述为严格的 Full Documents 端到端跨页恢复结果，也不能与不使用真值筛页的公开结果直接公平排名。

新的严格流程已经完成小规模验证，但 dots.ocr 全量推理计算成本较高。目前暂不将其作为核心研究的前置阻塞项，是否补齐全量结果需要结合论文对照需求和可用算力决定。

## 4. 当前结果说明了什么

### 4.1 页面级表格结构仍有改进空间

TATR 的软相似度较高，但严格完全匹配率明显更低。这说明模型经常能够恢复大部分结构，却仍可能因为局部行列、表头或合并单元格问题而无法得到完整正确的表格。

PubTables-v2 Cropped Tables 专门保留长表和宽表，本身就是对旧模型较困难的分布。项目使用的又是公开 TATR-v1.1-Pub，而不是 PubTables-v2 论文中的定向训练版本，因此这组结果更适合作为公开旧模型在新困难数据上的可复现基线。

### 4.2 页面抽取不是最终研究问题

即使单页表格结构完全正确，跨页恢复仍需要解决：

- 哪些页面片段属于同一张表；
- 不同页面之间的列如何对应；
- 后续页面的重复表头是否应该移除；
- 页面边界处的行或单元格是否需要合并；
- 多页结果如何在全局约束下形成一致的逻辑表格。

因此，本项目不应退化为重新训练一个通用 OCR 模型，也不应只做 continuation 二分类。

### 4.3 continuation 判断正确仍不等于整表恢复正确

[PubTables-v2](https://arxiv.org/abs/2512.10888)、[OCRFlux](https://github.com/chatdoc-com/OCRFlux) 和 [MinerU-Popo](https://arxiv.org/abs/2605.24973) 都表明，续接判断或局部分页边界决策可以取得较高准确率。但这些局部指标不能直接代表最终完整逻辑表格的严格正确率。

真正的研究空间在于：把续接、列对应、重复表头、拆分行和拆分单元格放入统一的结构表示，并通过全局约束完成最终重建。

## 5. 为什么没有测试更多相关模型

未测试其他模型不能统一解释为“都没有开源”，需要分情况说明。

### 5.1 TATR-v1.2 和 POTATR

[TATR-v1.2 / PubTables-v2](https://arxiv.org/abs/2512.10888) 和 [POTATR](https://arxiv.org/abs/2606.09788) 与当前课题高度相关，也已经报告论文结果。但截至项目核验日期，没有找到与论文结果完全对应的官方 checkpoint 和完整复现制品。

因此，当前做法是：

- 把论文结果作为外部参照；
- 不把未复现的结果写成项目实验结果；
- 持续关注官方发布；
- 如果后续研究确实需要，再自行训练并明确标注为“项目复现版本”。

### 5.2 MinerU-Popo

[MinerU-Popo](https://arxiv.org/abs/2605.24973) 已经公开代码和模型，并直接研究文档截断恢复。它报告的 `92.7%` 是分页边界处的局部合并决策准确率，不是最终整张跨页表格的 `Acc-Con`，因此不能与本项目当前结果直接进行数值高低比较。

MinerU-Popo 仍然是非常重要的后处理基线。它值得优先进行接口和许可审计，并在统一的 PubTables-v2 输入和最终整表指标下重新评估。

### 5.3 其他通用 OCR/VLM

其他开源或商业 OCR/VLM 可以作为扩展对照，但继续增加同类模型不会自动形成研究贡献。现阶段更重要的是建立与核心科学问题直接相关的比较：

- 页面级结构基线；
- continuation 基线；
- 直接纵向拼接基线；
- 局部边界恢复基线；
- 多关系结构对齐与约束重建方法。

## 6. 与相关研究相比，本项目计划做什么

| 相关方向 | 已解决的主要问题 | 尚未充分解决的问题 | 本项目可借鉴之处 |
| --- | --- | --- | --- |
| [Table Transformer / TATR](https://arxiv.org/abs/2110.00061) | 单张表格的行列、表头和单元格结构 | 不负责文档级跨页关系 | 显式、可解释的页面结构表示 |
| [PubTables-v2](https://arxiv.org/abs/2512.10888) | 公开完整文档基准、续接标签和统一评测 | 简单合并仍难保证严格整表正确 | 官方页面对标签和 Full Documents 协议 |
| [POTATR](https://arxiv.org/abs/2606.09788) | 轻量页面级 image-to-graph 抽取 | 跨页恢复仍依赖外部续接和合并 | 页面结构图表示 |
| [OCRFlux](https://github.com/chatdoc-com/OCRFlux) | 跨页元素定位和合并 | 构造数据与自然跨页文档仍有差异 | 分阶段检测、合并索引和合成样本 |
| [MinerU-Popo](https://arxiv.org/abs/2605.24973) | 通用文档后处理和分页边界局部恢复 | 尚未在 PubTables-v2 上报告最终整表严格指标 | 与上游解析器解耦的后处理接口和局部关系分解 |

本项目计划研究的核心差异是：

1. 在公开 PubTables-v2 Full Documents 上进行端到端验证；
2. 不只判断是否续接，而是联合建模多种跨页结构关系；
3. 使用全局一致性约束生成最终逻辑表格；
4. 同时报告局部关系指标和整表严格指标；
5. 通过 oracle 与 predicted 输入区分页面抽取、续接判断和结构重建的误差来源。

## 7. 下一阶段计划

### 阶段一：分层误差分析与结构消融

从当前 TATR 结果中抽取具有代表性的长表、宽表、复杂表头和 spanning cell 样本，分析主要结构错误，并通过 oracle 行数、列数、表头和 span 消融确定优先改进方向。

目标不是逐个查看全部样本，而是用分层抽样建立可量化、可复核的错误证据。

### 阶段二：最小跨页基线

使用 PubTables-v2 官方 continuation 标签建立：

1. continuation 判断基线；
2. continuation 后直接纵向拼接基线；
3. oracle continuation 与 predicted continuation 对照；
4. MinerU-Popo 等局部后处理基线。

该阶段要明确区分页面抽取错误、续接错误和拼接错误。

### 阶段三：核心方法

构建类型化的跨页结构关系，包括：

- `continuation-of`；
- `column-aligned-with`；
- `repeated-header-of`；
- `split-row-of`；
- `split-cell-of`；
- `same-logical-table`。

随后通过结构约束解码生成完整逻辑表格，并验证各类关系和约束对严格整表指标的贡献。

### 阶段四：完整论文评测

- 分开报告 `PDF-text-assisted` 和 `image-only`；
- 在 Full Documents 全部页面上评测；
- 报告 GriTS、TEDS、Acc 和局部关系指标；
- 进行 oracle/predicted、关系类型和约束解码消融；
- validation 用于研究开发，test 只用于最终评估。

## 9. 3–5分钟口头汇报稿

老师好，我目前研究的是 PubTables-v2 上的文档级跨页表格恢复。这个任务不仅要识别每一页中的表格，还要判断不同页面上的表格片段是否属于同一张逻辑表，并处理列对应、重复表头、拆分行和拆分单元格，最终恢复完整表格。

目前我已经完成了数据版本固定、数据标准化、评测流程和第一个正式页面级基线。TATR-v1.1-Pub 在 Cropped Tables validation 全部13,384张长表和宽表上的正式结果是：GriTS-Top 0.8848、GriTS-Con 0.8704、Acc-Top 0.3897、Acc-Con 0.3827。这个结果说明模型能够恢复较多局部结构和内容，但对于困难表格，整体严格正确率仍有较大的提升空间。

这项结果目前只是页面级结构基线，还不是跨页恢复结果。TATR本身不负责判断两个页面是否续接，也不处理跨页列对应、重复表头和页面边界处的拆分行。因此，真正的研究问题仍然在文档级结构关系和最终重建。

dots.ocr 代表纯图像路线。接管项目之前已经在 Full Documents validation 的表格页上做过一次较大规模运行，覆盖935篇文档中的3,522个表格页，结果是 GriTS-Top 0.6564、GriTS-Con 0.6216、Acc-Top 0.2760、Acc-Con 0.1380。这说明 dots.ocr 具备一定的整页表格抽取能力，是一个重要的 image-only 参考。不过，该运行只处理了有真值表格的页面，也没有执行跨页合并，所以不能当作严格的完整文档跨页恢复成绩。新的严格流程已经可以运行，但全量计算成本较高，所以暂时没有把它作为当前研究的前置条件。

没有测试TATR-v1.2和POTATR，主要是因为目前没有核验到与论文完全对应的官方checkpoint和完整复现制品，因此现在只引用论文结果作为外部参照。MinerU-Popo已经公开代码和模型，而且直接涉及分页边界恢复，下一步值得优先审计；但它的局部决策准确率不能直接等同于最终整表正确率。

从相关研究和当前基线看，单纯把continuation判断做好，或者把两页结果直接纵向拼接起来，并不能保证完整表格严格正确。我认为更有价值的研究方向是联合建模跨页列对应、重复表头、拆分行、拆分单元格和全局表格归属，并通过约束重建生成最终逻辑表格。

下一步我计划先做分层误差分析和结构消融，然后建立continuation加直接拼接的最小跨页基线，并审计MinerU-Popo。在这些证据明确后，再设计多关系结构图和约束解码方法。

这次希望重点请老师讨论：是否认可这个研究主线；dots.ocr全量是否值得现在投入算力；MinerU-Popo是否优先接入；以及TATR-v1.2和POTATR是等待官方权重还是后续自行复现。

## 10. 导师可能追问与建议回答

### 为什么目前重点测试 TATR 和 dots.ocr？

两者分别代表 `PDF-text-assisted` 的显式结构模型和 `image-only` 的端到端文档视觉模型。当前阶段先用它们建立两条主要技术路线的评测基础；增加模型数量只有在能够提供新的能力对照时才有意义。

### 为什么没有测试 TATR-v1.2 和 POTATR？

论文结果已经公开，但尚未核验到与论文完全对应的官方 checkpoint 和完整复现制品。当前引用论文结果作为外部比较，不把自行推测的实现当成官方复现。

### 当前 TATR 结果是否说明模型不可用？

不是。它能够较好地恢复局部结构，并完整恢复一部分困难表格，因此可以作为后续跨页方法的页面解析输入。但它仍需要结构改进，而且本身不包含跨页关系与重建模块。

### 为什么不先把 dots.ocr 全量跑完？

全量计算成本较高，而当前核心研究问题并不依赖 dots.ocr 全量结果才能启动。先确认研究主线并建立跨页最小基线，可以避免在研究目标尚未冻结时投入大量算力。

### 当前结果是否足以形成论文？

当前结果足以建立问题背景、评测协议和基线证据，但还不足以形成论文贡献。论文仍需要明确的新方法、与直接拼接及相关后处理方法的公平对照、消融实验和完整文档评测。

### MinerU-Popo 已经报告较高准确率，我们还有什么空间？

MinerU-Popo 的高准确率对应分页边界处的局部决策，而不是最终整张跨页表格的严格恢复率。本项目关注多关系联合建模、全局一致性和公开 Full Documents 基准上的最终整表结果，两者研究范围不同，但 MinerU-Popo 是必须纳入的重要基线。

## 11. 当前可陈述与不可陈述的结论

可以陈述：

1. 已建立固定数据版本和可重复的评测流程；
2. 已完成 TATR-v1.1-Pub 的 Cropped Tables validation 全量评测；
3. 当前页面级基线显示困难表格仍有明显的结构改进空间；
4. dots.ocr 已有较大规模的 Full Documents 表格页逐页抽取结果，可作为 `image-only` 页面级参考；
5. 下一步研究应聚焦多关系跨页结构对齐与约束重建。

暂时不能陈述：

1. 当前已经完成了跨页表格恢复方法；
2. dots.ocr 已完成严格 Full Documents 全量评测或跨页合并；
3. TATR-v1.2 或 POTATR 已被项目复现；
4. 所有其他模型都因为没有开源而无法测试；
5. 当前结果已经超过公开方法或足以支持最终论文结论。
