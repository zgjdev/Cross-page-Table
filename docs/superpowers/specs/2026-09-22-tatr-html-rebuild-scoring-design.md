# TATR HTML 重建与重新评分设计

日期：2026-09-22

## 背景

当前 TATR-v1.1-Pub Cropped Tables validation 结果中的预测 HTML 将表头写成 `<thead><th>...</th></thead>`，缺少标准的 `<tr>`。GriTS 的 HTML 解析器只在读取 `<tr>` 时推进网格行，因此这种序列化会错误计算表头行号，并可能扰乱行数、列数和 span。24 张分层样本的只读内存对照显示，仅补齐表头 `<tr>` 后，平均 `GriTS-Top` 从 `0.7838` 提升到 `0.9212`，平均 `GriTS-Con` 从 `0.7506` 提升到 `0.9047`，完全匹配由 `0/24` 变为 `9/24`。

## 目标

1. 修正 `cells_to_html()` 生成的表头层级。
2. 使用已有预测记录中的 `raw_output.cells` 重建规范 HTML，不重新执行 GPU 推理。
3. 将重建预测和新指标写入新的时间戳目录，保留所有旧预测、日志和指标。
4. 在后台执行完整 13,384 张 validation 表格的离线评分，并提供可审计的运行状态和耗时估计。

## 方案

### HTML 序列化

`cells_to_html()` 应生成标准表格层级：

- 表头行：`table > thead > tr > th`
- 正文行：`table > tbody > tr > td`
- 连续表头单元格属于同一个表头行；多层表头中的每一行均拥有独立的 `<tr>`。
- 保留当前 `rowspan`、`colspan` 和文本内容。

### 重建入口

新增流式重建与评分脚本，输入为：

- 旧 `predictions.jsonl`；
- 固定 validation manifest；
- 固定 PubTables-v2 Cropped Tables 真值目录。

对每条成功预测，从 `raw_output` 读取 `cells`，调用修正后的 `cells_to_html()` 重新生成 `tables_html`。推理错误和无有效 cell 的记录保持原状态。脚本不得修改旧文件，必须写入新的输出目录。

重建完成后复用现有完整覆盖门禁和 GriTS 评分逻辑，输出：

- 重建后的预测 JSONL；
- metrics JSON；
- failures JSONL；
- 输入输出校验信息和运行 manifest。

### 安全与运行方式

- 不下载数据到本地。
- 不覆盖或截断服务器已有预测、结果和日志。
- 全量运行使用新的 UTC 时间戳目录。
- 任务只使用 CPU，不申请 GPU。
- 正式后台启动前先运行单元测试、24 张固定抽样验证和一个计时样本。
- 后台任务记录 PID、开始时间、结束时间、退出码和日志。

## 测试与验收

采用测试驱动流程，先增加能在当前实现上失败的回归测试，再修改生产代码。

必须覆盖：

1. 单层表头生成 `thead > tr > th`。
2. 多层表头的每层均生成独立 `tr`。
3. 正文位于 `tbody > tr > td`。
4. `rowspan`、`colspan` 和文字保持不变。
5. 生成 HTML 经项目固定 GriTS 解析器回环后，网格行列、拓扑和内容与输入 cells 一致。
6. 重建脚本保持输入记录数、ID、状态和覆盖范围不变。
7. 两次小样本重建评分结果完全一致。

只有上述测试通过，且固定抽样中已知的9张表恢复为 exact match，才允许启动后台全量任务。

## 非目标

- 本次不修复模型本身的行列、span 或内容预测错误。
- 本次不重新运行模型推理。
- 本次不调整模型阈值或使用 test split 调参。
- 本次不把修复后的抽样结果直接当作完整 validation 结论。
