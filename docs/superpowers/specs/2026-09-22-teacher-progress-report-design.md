# 导师阶段进展汇报文档设计

日期：2026-09-22

状态：待用户审阅

目标文件：`docs/reports/teacher-progress-report-2026-09-22.zh-CN.md`

## 1. 文档定位

本文件设计一份可直接发送给导师、同时可以作为现场汇报底稿的中文阶段进展报告。报告不是结题材料，也不把尚未完成的 dots.ocr 严格全量实验或跨页恢复方法写成已完成成果。

目标读者是熟悉计算机视觉或文档理解研究、但不一定了解本项目执行细节的导师。正文预计 5–8 页等量内容，优先保证科学结论准确、实验边界清楚和下一步可讨论，而不是堆叠工程日志。

## 2. 核心叙事

报告采用一条主线：

1. 研究目标是 PubTables-v2 Full Documents 上的文档级跨页表格恢复；
2. 当前先建立可复现的页面/表格抽取基线和严格评测协议；
3. 已完成 TATR-v1.1-Pub 在 Cropped Tables validation 上的全量评测，并核验接管前 dots.ocr Full Documents 历史结果；
4. 现有模型在局部软相似度和整表严格正确率之间存在明显差距，且缺少显式跨页结构恢复能力；
5. 最相关的 TATR-v1.2/POTATR 暂无已核验的官方 checkpoint 或完整复现制品，因此当前采用公开可获得模型建立下界，并将论文报告值作为外部参照；
6. 后续研究重点应由“继续堆通用 OCR 模型”转向列对应、重复表头、拆分行/单元格和约束重建。

## 3. 正文章节

### 3.1 执行摘要

用一页以内回答：做了什么、得到什么、为什么结果仍不足、为什么部分模型未测、希望导师决定什么。

### 3.2 研究背景与问题定义

说明 Cropped Tables、Single Pages 和 Full Documents 的区别，明确本项目最终目标是 Full Documents 跨页恢复，而 TATR Cropped 只是页面结构组件基线。

### 3.3 数据与评测协议

记录固定 PubTables-v2 revision、validation 样本量、输入赛道和指标含义。强调：

- `PDF-text-assisted` 与 `image-only` 分开报告；
- `GriTS` 是软相似度，`Acc` 是严格完全匹配；
- validation 用于开发，test 不用于调参；
- Full Documents 严格协议必须覆盖全部页面，不能按真值筛页。

### 3.4 已完成工作与结果

使用一张状态表和两张结果表呈现：

- TATR-v1.1-Pub Cropped 全量 13,384/13,384；
- 两次离线评分一致；
- 65 个推理失败如实报告；
- dots.ocr 新协议 smoke；
- 接管前 dots.ocr 历史 Full Documents 结果及其真值筛页限制。

### 3.5 未测试模型与原因

按模型类型分别说明，不作“所有未测模型都未开源”的笼统表述：

- TATR-v1.2/POTATR：最相关，但截至核验日期官方论文仍表述代码和模型将发布，现有官方 TATR 仓库只列出 PubTables-1M/TATR-v1.1 系列权重；
- Claude、Gemini、GPT：商业 API 模型，不是开放权重模型，可测试但存在成本、版本稳定性和复现性问题；
- 其他开源 VLM：权重可得，未测试主要是阶段范围和计算预算，不是不可获得。

### 3.6 结果不理想的原因

区分观察和推断：

- 已观察：TATR 的 GriTS 尚可而 Acc 很低；precision 低于 recall；65 个推理失败；
- 有证据的解释：TATR-v1.1 训练于 PubTables-1M，而 PubTables-v2 Cropped 专门包含长表和宽表；exact match 对任一结构或文本错误敏感；TATR 本身不处理跨页关系；
- 待验证推断：额外/碎片化结构、复杂表头、合并单元格和文字归属可能是主要错误来源，需要分层误差分析确认。

### 3.7 改进方向与研究贡献候选

分两层：

- 基线工程：错误分类、PubTables-v2 继续微调、结构约束、PDF text 分配和官方新权重发布后的补测；
- 论文方法：continuation 后的显式列对应、重复表头识别、拆分行/单元格恢复、类型化关系图和约束解码。

### 3.8 下一阶段计划

按依赖关系组织，而非给出未经确认的日历承诺：

1. 完成 TATR 分层误差分析和证据链补全；
2. 建立 continuation 与直接纵向拼接基线；
3. 建立 oracle 与 predicted continuation 两种设置；
4. 开发对齐感知重建方法及消融；
5. 根据导师对算力投入的判断，再决定何时补齐 dots.ocr 全量。

### 3.9 需要导师讨论和决定的问题

聚焦三个决策：研究主线是否转向跨页结构对齐；是否投入多卡补 dots.ocr 全量；是等待 TATR-v1.2/POTATR 官方发布，还是自行训练近似基线。

- 所有项目数字来自保存的 predictions、metrics、checksums 或已有实验记录；
- 公开模型状态以 2026-09-22 核验到的官方论文、官方 GitHub 和官方 Hugging Face 页面为准；
- 不把论文报告值写成项目复现值；
- 不把 `GriTS` 解释为完全正确率；
- 不把历史 3,522 页 dots.ocr 结果写成严格 13,871 页全量结果；
- 不把商业 API 模型简单归类为“拿不到参数所以不能测试”；
- 对 TATR 失败原因使用“证据支持”或“待误差分析验证”，避免因果越界。

## 6. 验收标准

最终报告必须满足：

1. TATR 指标、样本数、错误数和证据路径与 `docs/research-progress.zh-CN.md` 一致；
2. dots.ocr 历史结果明确标注真值筛页和无跨页合并；
3. 未测模型原因按“未发布权重 / 商业 API / 可得但未纳入阶段范围”分开；
4. 下一步计划直接回应当前结果暴露的问题；
5. 包含可直接朗读的汇报稿和至少 8 个可能追问；
6. 无未完成标记、占位符、虚构命令、未核验指标或过度结论；
7. 文档默认中文，模型名、指标名、路径和配置保留英文。
